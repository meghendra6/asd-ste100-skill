# 한국어 회귀 테스트 케이스

각 케이스를 새 세션에서 실행하고, 통과 기준을 전부 확인한다. 실행 방법은
`tests/README.md`에 있다.

## K1 — 전보체 상태 보고 (형태소 복원 + 헤지 보존)

**프롬프트:**

> 이 상태 보고를 기계가 오독하지 않게 고쳐줘:
>
> 배포 실패. 원인 분석 중. config 오타로 추정. 수정 후 재배포 예정.

**통과 기준:**

- [ ] 모든 문장이 조사와 어미를 갖추고 종결어미로 끝난다.
- [ ] "추정"의 헤지가 살아 있다. "config 오타가 원인입니다"로 승격하면 실패다.
- [ ] 원문에 없는 원인 설명이나 일정이 추가되지 않았다.
- [ ] 출력은 재작성 텍스트뿐이다. 서두, 모드 안내, 변경 요약이 없다.
- [ ] `유지:`/`중의성:`/`추가:` 라벨이 없다. 이 입력에는 보고할 것이 없다.

## K2 — 이중피동·번역투 도구 설명

**프롬프트:**

> 이 도구 설명의 중의성을 제거해줘:
>
> 본 기능은 사용자에 의해 업로드된 파일들의 변환을 수행하는 것을 가능하게 하며, 변환이 완료되어지면 결과가 저장소에 반영되어집니다.

**통과 기준:**

- [ ] 이중피동("완료되어지면", "반영되어집니다")이 없다.
- [ ] 번역투("~하는 것을 가능하게 하며", "~에 의해")가 없다.
- [ ] 명사화("변환을 수행")가 동사("변환합니다")로 풀렸다.
- [ ] 각 동작의 행위 주체가 문장에 있다 (이 기능이 변환한다, 이 기능이 저장한다 등).
- [ ] 한 문장에 주장이 하나씩이다.

## K3 — 진짜 중의성 (`중의성:` 라벨)

**프롬프트:**

> 이 문장을 에이전트가 오독하지 않게 고쳐줘:
>
> 클라이언트가 서버에 인증서를 보내고, 그 다음 인증서를 갱신합니다.

**통과 기준:**

- [ ] 두 동작이 별도 문장으로 나뉘었다.
- [ ] 출력에 `중의성:` 라인이 있고, 두 읽기(클라이언트가 갱신 / 서버가 갱신)를 모두 이름 붙였다.
- [ ] 본문이 갱신의 주체를 임의로 정하지 않았다.
- [ ] 피동("인증서가 갱신됩니다")으로 행위자를 숨기지 않았다.

## K4 — 행동 없는 경고 (`추가:` 규율)

**프롬프트:**

> 이 지시문을 다듬어줘:
>
> 마이그레이션을 실행하세요. 실행 중에는 스키마 잠금이 발생할 수 있다는 점을 참고하시기 바랍니다.

**통과 기준:**

- [ ] 경고가 "참고하시기 바랍니다" 뒤에 파묻히지 않고 명확한 경고 문장이 되었다.
- [ ] 헤지("발생할 수 있다")가 살아 있다.
- [ ] 다음 둘 중 하나다: (a) 원문에 없는 행동이 추가되지 않았다. (b) 행동이 추가되었고, `추가:` 라인이 추가된 문장과 철회 조건을 밝힌다.
- [ ] 조용한 추가(라벨 없는 추가 행동)는 실패다.

## K5 — 이미 준수하는 입력

**프롬프트:**

> 이 텍스트에 STE100을 적용해줘:
>
> 큐가 가득 찼습니다. scheduler가 새 작업을 거부합니다. 큐 용량을 늘리세요.

**통과 기준:**

- [ ] 출력이 원문을 그대로 두거나, 이미 규칙을 준수한다고 밝힌다.
- [ ] 억지 변경이 없다. 준수하는 텍스트를 바꾸면 실패다.

## K6 — 길이 압박에서 정밀도 보존

**프롬프트:**

> 이 지시문을 다듬어줘:
>
> 재시작은 롤링 업데이트가 진행 중이지 않은 경우에 한하여 프로덕션 네임스페이스 외부의 파드에 대해서만 수행되어야 합니다.

**통과 기준:**

- [ ] 두 조건이 모두 출력에 있다: 롤링 업데이트가 진행 중이지 않을 것, 프로덕션 네임스페이스 외부일 것.
- [ ] 피동("수행되어야 합니다")이 명령형이나 능동으로 바뀌었다.
- [ ] 길이 기준을 맞추기 위해 조건을 삭제하지 않았다. 필요하면 문장을 나눴다.
- [ ] 조건을 담느라 문장이 길게 남았다면 `유지:` 라인으로 밝혔다 (선택 조건: 나누기로 해결했다면 라벨이 없어도 통과).
